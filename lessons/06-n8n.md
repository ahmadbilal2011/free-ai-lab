# Lesson 06 — n8n online and safe

**Goal:** install **n8n** on the server, publish it safely on its own HTTPS address, connect it to the AI
switchboard (Lesson 05), and build your first two workflows. After this lesson, the n8n track teaches n8n one step at a time.

**Time:** about 30 minutes. **Cost:** $0. n8n is free to self-host for personal use.

**Before you start:** Lessons 01–03 and 05 are done. Apache is running on the server (it also serves the separate
SAR→PKR calculator site, which this lesson never touches).

**Status:** ✅ Tested (2026-11-16).

---

## Part A — What n8n is

**n8n** ("n-eight-n") builds automations from **nodes** connected on a canvas: "when *this* happens, do *that*, then *that*".

```
 [Trigger] ──► [Node] ──► [Node] ──► [Node]
 "a Telegram    "ask the    "voice or    "reply on
  message"       AI"         text?"       Telegram"
```

| Why n8n | Detail |
|---|---|
| **Light on the server** | n8n only *coordinates*; the thinking happens in free cloud models through Bifrost |
| **Hundreds of connectors** | Telegram, Google, Microsoft, HTTP requests… mostly no code |
| **AI built in** | Chat models, AI Agents with tools, memory |
| **Visual** | You see every step and its data: easy to learn and debug |
| **Your data stays here** | Workflows and credentials live on your server, encrypted |

> **Licence:** n8n is "fair-code": **free to self-host for personal and internal use**. You just can't resell it as a service.

| Word | Meaning |
|---|---|
| **Workflow** | One automation: a chain of nodes |
| **Trigger** | The node that starts it: a schedule, a click, a message… |
| **Node** | One step: "call AI", "send message", "if / else", "HTTP request" |
| **Credential** | A saved login or key that nodes use. n8n **encrypts** these |
| **Execution** | One run of a workflow, with the data at every step |
| **Published** | Switched on, so its trigger runs by itself |
| **Expression** | `{{ … }}`: use data from earlier steps, e.g. `{{ $json.text }}` |

## Part B — How it's published: one public door, five locks

```
Internet ──► Apache :443 ──┬── SAR calculator site (unchanged, its own name + certificate)
                           ├── n8n-<ip>.sslip.io ──► 127.0.0.1:5678 (n8n)
                           └── ai-<ip>.sslip.io  ──► Bifrost's web page (Lesson 05)
n8n ──► http://bifrost:8080/v1   (inside the server only)
```

Apache already owns ports 80/443, so it is the single public door, with a **separate name** per app.
`sslip.io` is free: `n8n-1-2-3-4.sslip.io` always points to IP `1.2.3.4`, so no domain is needed.
(Own domain? Point a name at the server and run with `N8N_DOMAIN=n8n.yourdomain.com`.)

| Lock | What it stops |
|---|---|
| 1. HTTPS (Let's Encrypt, auto-renewed) | nobody can read passwords on the way |
| 2. Owner login created **from the server** (the public setup page is blocked) | nobody can claim your empty n8n first |
| 3. **2FA** in n8n (you switch it on) | a leaked password is not enough |
| 4. fail2ban on the n8n login | 5 failed logins in 10 minutes = that IP blocked for 1 hour |
| 5. n8n's port 5678 stays server-only | the only way in is Apache + HTTPS |

Only `/webhook/…` addresses are meant for outside apps (like Telegram); each has a long random ID and only answers while its workflow is published.

> **Why no extra Apache password box?** It was tried first. n8n's page loads some files without the saved
> browser password, so the box kept popping up again and again. n8n's login + 2FA + fail2ban gives the same
> protection without that problem.

Settings in [`stacks/jarvis/compose.yaml`](../stacks/jarvis/compose.yaml): SQLite (no extra database),
`mem_limit: 1g`, no telemetry, failed runs kept 14 days and successful ones not stored, healthcheck + autoheal,
data in `~/lab/jarvis/n8n`.

## Part C — Install (one command)

On the server, as `ubuntu`, **without** `sudo`:

```bash
curl -fsSLO https://raw.githubusercontent.com/ahmadbilal2011/free-ai-lab/main/scripts/06-install-n8n.sh
bash 06-install-n8n.sh --fresh
```

It creates `~/lab/jarvis` with a private `.env` (random **encryption key**, public name, time zone), gets the
certificate, adds the Apache site and fail2ban jail, starts n8n, then asks for your **email, name and password**
(typed hidden) and creates your n8n login from the server.

**Expected tests at the end:**
- `https://<name>/healthz` → **200**
- owner setup from the internet → **403**
- `http://<ip>:5678` → **000** (not reachable)

Then open the link, log in, and go to **Settings → Personal → Enable 2FA**.

| Command | What it does |
|---|---|
| `bash 06-install-n8n.sh` | Update n8n; workflows and key kept |
| `bash 06-install-n8n.sh --fresh` | Brand-new n8n. Old data is **moved** to `~/lab/jarvis/n8n.old-<date>`, never deleted |
| `bash 06-install-n8n.sh --owner` | Create the login from the server if it wasn't created |
| `bash 06-install-n8n.sh --off` | Take the web page offline (n8n keeps running privately) |

> **Turn the n8n Assistant off** (the setup card that asks for a model, code sandbox and web search): on a
> self-hosted server it needs a privileged code sandbox, which is too risky next to a customer website.
> Click *Turn off for this instance*.

### What survives what

| Event | Workflows and credentials |
|---|---|
| n8n restarts, updates, re-running the installer | ✅ Kept |
| Server reboots | ✅ Kept |
| `~/lab/jarvis/n8n` deleted | ❌ Gone, unless restored (Lesson 08) |
| `~/lab/jarvis/.env` (encryption key) lost | ❌ Credentials unreadable; workflows survive. **Save the key in a password manager** |

## Part D — Connect n8n to the AI switchboard

In n8n: **Credentials → Create → OpenAI**:

| Field | Value |
|---|---|
| API Key | a Bifrost **virtual key** (Lesson 05), e.g. the `smart` one |
| Base URL | `http://bifrost:8080/v1` |

Name it `AI smart` (the title at the top of the window). "Connection tested successfully" = n8n reaches Bifrost.
Repeat for `AI quick` / `AI code` if you created those keys.

## Part E — Workflow 1: "Hello AI" (manual)

1. **Create workflow** → `Hello AI` → trigger **Trigger manually**.
2. **+** → **Basic LLM Chain** · Source for Prompt *Define below* · Prompt: `You are my personal assistant. Greet me in one short sentence and suggest one small thing I could automate in my day.`
3. **Model** connector → **OpenAI Chat Model** · credential `AI smart` · Model **By ID**, e.g. `groq/openai/gpt-oss-120b`.
4. **Execute workflow** and open the chain node to see input, output and the answer. Then check Bifrost's **Logs** page to see which provider answered.

## Part F — Workflow 2: a scheduled job

1. Create `Hourly tip (practice)` · trigger **On a schedule → Every hour**.
2. **Basic LLM Chain** with credential `AI quick` (or `AI smart`) and the prompt `Give one short, practical Linux command tip with an example. Max 2 sentences.`
3. **Publish** (top right), check it ran, then **Unpublish** so no free quota is wasted on practice.

## If something goes wrong

| Problem | Fix |
|---|---|
| Browser asks for a password again and again | An old Apache password box is still active: re-run `bash 06-install-n8n.sh` (it removes it) |
| Setup page shows "Request failed with status code 403" | Expected: setup is blocked from the internet. Run `bash 06-install-n8n.sh --owner` on the server |
| Credential test fails | Base URL exactly `http://bifrost:8080/v1`; the key is a Bifrost **virtual key**; `docker ps` shows `bifrost` |
| `EACCES` in `docker logs n8n` | `sudo chown -R 1000:1000 ~/lab/jarvis/n8n && docker restart n8n` |
| `Mismatching encryption keys` | The key in `~/lab/jarvis/.env` changed. Put back the one from your password manager |
| Schedules run at the wrong hour | Set `TZ_NAME=Asia/Riyadh` (any `Area/City`) in `~/lab/jarvis/.env`, then re-run the installer |

Useful checks:

```bash
docker logs --tail 50 n8n
sudo fail2ban-client status n8n-login        # who is banned
sudo tail -f /var/log/apache2/n8n-access.log # who is knocking
sudo certbot renew --dry-run                 # certificate renewal works
```
