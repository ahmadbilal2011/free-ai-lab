# Lesson 04 — Run my own AI: Ollama + Open WebUI

**Goal:** a private, ChatGPT-style AI running on your own server, using only open-source software, with automatic recovery if something freezes.

**Time:** about 20–40 minutes (mostly waiting for downloads).

**Cost:** $0.

**Before you start:** Lesson 03 is done and `docker ps` works without `sudo`.

---

## Part A — How the pieces fit together

```
Your browser (Windows)
     │  Tailscale private HTTPS (Lesson 05)
     ▼
┌──────────── Oracle VM ─────────────────────────────────────┐
│                                                            │
│  open-webui  (port 3000, server-only)                      │
│     │  asks questions over the internal Docker network     │
│     ▼                                                      │
│  ollama      (port 11434, server-only)                     │
│     │  loads the model into RAM and runs it on the 2 CPUs  │
│     ▼                                                      │
│  [volume: models]   [volume: users, chats, settings]       │
│                                                            │
│  autoheal  → watches both, restarts any that freeze        │
└────────────────────────────────────────────────────────────┘
```

| Part | Job |
|---|---|
| **Ollama** | Downloads open-source AI models and runs them. Has no screen of its own; other programs talk to it. |
| **Open WebUI** | The website you chat in: accounts, chat history, model picker, file uploads. |
| **autoheal** | Our safety net from the Kubernetes discussion: restarts any container Docker marks *unhealthy*. |

## Part B — Choosing a model (and honest expectations)

A model's size is its number of **parameters** (B = billion). Bigger is smarter but needs more RAM and is slower. Ollama's models are already **quantized** (compressed) so they fit in less memory.

Our budget: 12 GB RAM, minus ~1 GB for Ubuntu and ~1 GB for Open WebUI ≈ **10 GB for the model**. No GPU, just 2 Arm CPU cores.

| Model | Download | Speed on our server | Good for |
|---|---|---|---|
| `llama3.2:1b` | ~1.3 GB | Fastest | Very simple questions, quick tests |
| **`llama3.2:3b`** ⭐ default | ~2 GB | Usable | Everyday questions, drafting, summaries |
| `qwen3:4b` | ~2.5 GB | A bit slower | Reasoning, coding help |
| `gemma3:4b` | ~3.3 GB | A bit slower | Writing, general knowledge |
| 7–8B models (e.g. `qwen2.5:7b`) | ~4.5–5 GB | Slow | Better answers, but you'll wait |

Honest expectations:

- Replies appear **word by word, a few words per second** for 3–4B models.
- The **first question after a while is slower** (often 10–30 s), because the model must load into RAM. We keep it loaded for 30 minutes after last use.
- These small models are useful, but **not as capable as ChatGPT or Claude**, and they can be confidently wrong. Check important facts.

Browse more at <https://ollama.com/library>. Measure speeds yourself and write them in `PROGRESS.md`. That's real benchmarking experience.

## Part C — What's in the stack file

The full file is [`stacks/ai/compose.yaml`](../stacks/ai/compose.yaml) (every line is commented). The important choices:

| Setting | Why |
|---|---|
| Ports `127.0.0.1:...` | Nothing is reachable from the internet. |
| `OLLAMA_MAX_LOADED_MODELS: 1`, `OLLAMA_NUM_PARALLEL: 1` | Only one model in RAM and one question at a time: right for 12 GB / 2 CPUs. |
| `OLLAMA_KEEP_ALIVE: 30m` | Model stays loaded 30 min, so follow-up questions are fast. |
| `OLLAMA_BASE_URL: http://ollama:11434` | Containers in one stack find each other **by name**. |
| `depends_on ... service_healthy` | Open WebUI waits until Ollama is actually answering. |
| **healthcheck** on both | Docker regularly asks each app "are you OK?". |
| `start_period: 5m` on Open WebUI | Its first start downloads extra files. Don't mark it unhealthy too early, or autoheal would restart it in a loop. |
| `label autoheal: "true"` | Tells autoheal to watch this container. |
| `WEBUI_SECRET_KEY` from `.env` | Signs your login sessions. Kept in a private `.env` file, **never committed** (it's in `.gitignore`). |
| Volumes `ollama`, `open-webui` | Models and chats survive updates and restarts. |

### The two kinds of self-healing we now have

| Situation | Who fixes it |
|---|---|
| Container **crashes** (process exits) | Docker's `restart: unless-stopped` |
| Container **runs but freezes** (healthcheck keeps failing) | **autoheal** restarts it |
| **Server reboots** | Docker starts at boot and brings everything back |

### A security note on autoheal

To restart other containers, autoheal needs access to the **Docker socket**, which is root-level power over the server. That's why we use a well-known image and give it nothing else. (Kubernetes solves this differently, with a built-in "kubelet". A good thing to compare in the Phase 2 Kubernetes track.)

## Part D — Install (one command)

On the VM, as `ubuntu`, **without** `sudo`:

```bash
curl -fsSL https://raw.githubusercontent.com/ahmadbilal2011/free-ai-lab/main/scripts/04-install-ai.sh -o 04-install-ai.sh && bash 04-install-ai.sh
```

To start with a different model: `MODEL=gemma3:4b bash 04-install-ai.sh`

The script:

1. Checks Docker works, and that there's enough free disk
2. Starts **autoheal** in `~/lab/autoheal`
3. Creates `~/lab/ai/.env` with a random secret, then starts **Ollama + Open WebUI** in `~/lab/ai`
4. Downloads the model and asks it a test question. You'll see the AI's first answer in your terminal 🎉
5. Waits until Open WebUI is healthy (up to 10 minutes on first start) and prints how to open it

## Part E — Open it on your laptop and phone

Open WebUI only listens on the server itself (`127.0.0.1:3000`), so nothing is public. To reach it from your devices, go straight to **[Lesson 05 — Tailscale](05-tailscale.md)**. It gives you a private **https://** address that works on your laptop *and* phone, from anywhere, without opening any port.

**Create your Open WebUI account as soon as you can reach the page. The first account becomes the admin.**

### Useful Open WebUI settings (as admin)

- **Admin Panel → Settings → General → Default User Role**: keep new sign-ups as **pending**, so nobody else can use your AI without your approval.
- **Admin Panel → Settings → Models**: set your default model.

### Tune Open WebUI for a small CPU server (do this!)

Our first real chat went wrong in an instructive way. We asked *"Can you hear me?"* and `llama3.2:3b` tried to call a **calendar tool** (`create_calendar_event`), failed, and gave a confused answer.

**Why:** Open WebUI can give the model **tools** (functions it may call, like creating calendar events or searching). Big models use them sensibly; **small 3B models often call tools when they shouldn't.** Open WebUI also sends **extra background requests** after every message (chat title, tags, follow-up suggestions), and Ollama handles one request at a time, so you wait longer.

Fix it (menu names can differ slightly between Open WebUI versions):

1. **Turn off tools for the small model:** **Admin Panel → Settings → Models** → click `llama3.2:3b`:
   - **Builtin Tools** (shows *Time & Calculation, Ask User, Memory +8*): click it and **untick all of them**. This is where the calendar tool came from. (**Tools** usually already shows *None*.)
   - **Advanced Params**: if there's a **Function Calling** setting, set it to **Default** (not *Native*).
   - **Capabilities**: untick **Vision**; `llama3.2:3b` can't read images.
   - Click **Save & Update**.
2. **Turn off background tasks:** **Admin Panel → Settings → Interface** → switch off **Title generation, Tags generation, Follow-up generation** and **Autocomplete generation** → **Save**.
3. Start a **New Chat** (old chats keep their old settings).

Ask again. You should get a normal reply, sooner. Keep tools for later, when we try a bigger model.

### Optional fallback: SSH tunnel (PC only)

If Tailscale isn't available for some reason, an **SSH tunnel** can bring the port to your laptop through your SSH login:

```
Your browser → localhost:3000 on Windows ═══ encrypted SSH ═══► localhost:3000 on the VM → Open WebUI
```

Run this **in a PowerShell window on your Windows laptop** (not inside the VM), and leave it open:

```powershell
ssh -i $HOME\.ssh\free-ai-lab -N -L 3000:localhost:3000 ubuntu@<SERVER_IP>
```

- `-L 3000:localhost:3000` → "my laptop's port 3000 → the server's localhost:3000"
- `-N` → just hold the tunnel open; no shell (the window looks "stuck", which means it's working)

Then open **http://localhost:3000** in the laptop's browser. If port 3000 is busy on your laptop, use `-L 3001:localhost:3000` and `http://localhost:3001`.

## Part F — Managing models and the stack

Run these on the VM:

| Command | What it does |
|---|---|
| `docker exec ollama ollama list` | Downloaded models and their size |
| `docker exec ollama ollama pull qwen3:4b` | Download another model (also possible in Open WebUI) |
| `docker exec ollama ollama rm llama3.2:1b` | Delete a model to free disk |
| `docker exec ollama ollama ps` | Which model is loaded in RAM right now |
| `docker exec -it ollama ollama run llama3.2:3b` | Chat in the terminal (type `/bye` to exit) |
| `docker stats` | Live CPU and RAM per container |
| `cd ~/lab/ai && docker compose pull && docker compose up -d` | **Update** Ollama and Open WebUI (chats and models are kept) |

### Try it: watch self-healing happen

Crash Ollama on purpose, from inside the container:

```bash
docker exec ollama sh -c 'kill 1'      # stops Ollama's main process
sleep 15
docker ps --filter name=ollama         # "Up ... seconds": Docker restarted it
docker inspect -f 'Restarts: {{.RestartCount}}' ollama
```

Check the health status and what autoheal is doing:

```bash
docker ps --format 'table {{.Names}}\t{{.Status}}'   # look for (healthy)
docker logs autoheal                                  # restarts of frozen containers are logged here
```

## If something goes wrong

| Problem | Fix |
|---|---|
| Open WebUI page doesn't open | Is Open WebUI healthy (`docker ps`)? On first start, give it up to 10 minutes. Then see Lesson 05's troubleshooting. |
| Model list is empty in Open WebUI | Check `docker exec ollama ollama list`. If empty, pull a model. |
| Very slow or the server freezes | Try a smaller model. Check `free -h` and `docker stats`. Keep one model loaded at a time. |
| `open-webui` keeps restarting | `docker logs open-webui` and `docker logs autoheal`. Send the last lines. |
